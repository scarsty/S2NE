# 原事件指令与关卡数据

更新：2026-11-16。依据 `analysis/ida/opening.idb.asm`、原 `SUPERSP.BIN/PAL` 和当前解析器。本文是已确认格式及指令目录，不是“所有子指令已完整逆向”的声明。未知项保留数字，不猜测名称。

## 1. 执行模型

专用二进制事件表，由原生引擎解释；不是 x86 模拟器，也不是 Lua 等通用语言。回合、死亡、胜利、旗标变化等入口按原顺序扫描记录，条件成立后调用原生函数。对白、选择、移动和演出可以挂起执行，完成后继续；不能简单将全部事件展平成对白列表。死亡入口存在同步调用链及专用返回值，复刻的显式调用栈是保持该语义的实现，不证明资源中存在通用函数调用指令。

原分派：`41B5DF`；旗标扫描／消耗：`41B9A3`、`41BA56`；死亡：`41C02A → 41CA6E → 41FF30`。源码导航：[事件解析](../src/original_events.h)、[事件控制](../src/prologue.h)、[谓词](../src/original_script_predicates.h)、[死亡执行栈](../src/original_death_dispatch.h)、[关卡结算](../src/original_campaign.h)。

## 2. 关卡与事件位置

全部多字节整数为小端。BIN目录第1项起点：`u32(PAL,848)-11`。目录先有u16关卡数，后接每关30字节表头。表头+0的u32为相对目录起点的数据偏移，+4为数据长度，+8为单位数，+9地图号，+10音乐号，+25初始分段数，+26的u32为相对关卡数据起点的角色表偏移。角色记录101字节。

角色表之后的14字节区段头提供名称、简报、胜败说明的长度及条件项数；事件区起点由这些长度求和，不应搜索字符串猜偏移。详见 `OriginalEvents::load_stage_validated`。事件区先有u16事件数与u16后续数据长度，然后是20字节事件记录。

| 偏移 | 类型 | 含义 |
|---|---|---|
| +0 | u8 | 类型／操作码，0表示停用 |
| +1 | u16 | 子条件；使用时应遵守具体原函数的有符号解释 |
| +3 | i16 | 回合、角色或触发旗标等，随类型变化 |
| +5/+7/+9 | i16 | 三个参数，随子指令变化 |
| +11 | u8 | 完成后置1的旗标，合法号1–80 |
| +12 | u32 | 对白数据相对事件区起点的偏移 |
| +16 | 2字节 | 本文不定义；不可擅自清零 |
| +18 | u16 | 对白／选择行数；部分原入口按有符号数判断 |

完成通常将记录类型置0，并设置+11指定旗标；存档保存事件状态，复刻不修改原BIN。旗标表80项，源码下标为原编号减1。`clear_stage_flags`只清前40项，不等于全部80项跨关清空。

### 2.1 资源读取层次

关卡逻辑并不是从单个独立的“关卡文件”读取，而是先通过`SUPERSP.PAL`建立逻辑目录，
再从同目录下的`SUPERSP.BIN`和按资源域分区的`SUPERSP.DAT`/`SUPERSP.PRG`取数据。
当前合并资源读取器的入口是[resource_bundle.h](../src/resource_bundle.h)：

1. `SUPERSP.PAL`保存目录及偏移/长度索引；读取器校验目录表、资源域、逻辑长度和哈希。
2. `SUPERSP.BIN`、`KINDSP.BIN`、`ITEMSP.BIN`是共享逻辑表，不按战场地图号直接从DAT取。
   `OriginalEvents::create()`先读这些表，再由PAL第1组目录定位关卡表和能力/战斗配置。
3. `SUPERSP.DAT`和`SUPERSP.PRG`各有`primary/secondary`两个逻辑资源域。域不是随意选择的，
   由路线、进度和全局关卡字段计算；同一逻辑资源号在不同域可能对应不同内容。
4. `SUPERSP.CEL`主要是共享界面/压缩图形资源，不承载事件记录；地图和剧情数据的结构化
   读取应从BIN/PRG/DAT入口追踪，不能仅按CEL编号推导事件。

### 2.2 关卡表到地图的连接

`OriginalEvents::load_stage_validated()`读取关卡表头的`+9`地图号和`+10`音乐号；随后
`Battle::try_load()`用地图号访问`SUPERSP.PRG`的地图目录。PRG地图记录的已确认结构为：

- 地图目录先给地图数量和每个地图记录的相对偏移；记录开头为宽度`u16`、半高行数`u16`，
  运行时将高度解释为该值乘2。
- 记录头长度为28字节；`+28`开始是每格5字节的地图单元，按行优先读取：地面号`u8`、
  物件号`u16`、高程/属性字段`u16`。地图外的奇数行最后一列无效，不能按矩形全宽使用。
- 地图记录头的`+12`给出特殊记录数量所在的偏移基数，`+14`给出数量；每条特殊记录6字节，
  当前已确认其中带`0x8000`标志的坐标进入封锁/不可通过格集合。其余特殊记录字段仍未知。
- PRG另有动作序列目录、地面/物件属性表、移动规则和动态效果数据；它们由地图加载器和
  `OriginalDiscResources::try_dat_entry(domain, 6)`共同读取，不能把地图格5字节误当成完整移动规则。

因此扩展新剧情时，关卡事件表中的地图号必须同时在目标资源域的PRG地图目录中存在；只新增BIN
事件而不提供对应地图，运行时会在地图边界或动作/属性表校验处失败。

## 4. 已确认的子指令参数

- **5/0**：+3为触发旗标。选择以1开始写回该旗标，同时写原旗标12；之后消耗选择事件。5/1–4匹配该值，分支开始时清该触发旗标。不要将界面零基下标直接写入资源旗标。
- **7/0、7/1**：+5角色，+7/+9目的地；1分支带镜头跟随。寻路失败和事件消耗顺序仍按原函数，不另加瞬移兜底。7/2本批不解释。
- **8/0**：+5/+7镜头坐标，可附对白。**8/3**定位+5角色。**8/4**定位后等待100cs；+5非零且+7为0时按角色取坐标。**8/8**在同步状态处理器中为重绘／成功返回，不凭名称添加数值变更。其余子项须继续逐函数核对。
- **9/0**：旗标触发对白。**9/1、2**对+5/+7/+9中合法旗标做AND；**9/3、4**做OR；2和4仅在成功后清有效操作数。**9/6**将+5作为后续路线值。9/7本批不解释。
- **11/0–6**：+5角色。分别检查死亡20h、非死亡、符合440D4C身份资格、我方缺席、我方40h且非80h、我方80h、我方非40h且80h。不是统一用HP>0代替。0/4/5/6虽本资源未见，已有解析语义。
- **11/8**：队伍经验／成长事务，原462CB7。**11/11、12**：分别将+5有符号增量加到两种货币，原4214C1/4214D5，保留32位回绕；7/9须另核原处理，不从数字猜用途。
- **12/16**：+5角色、+7方向（低2位）。**12/25**：+5角色、+9写角色运行时WORD+0Ah的AI类别，原461149。不是角色职业编号。0/1/10/19/20/22/27/28分别涉及角色重置、演出、移除或控制事务，须按生产适配器区分；未展开项不视为无操作。
- **13/1**：+5原音效参数，经原音效入口及停止规则；**13/2**：+5音乐号；**13/3**：+5/+7/+9临时文本展示参数。后两项当前BIN未见，不删引擎支持。
- **14/0**：+5主体角色、+7关系对象（1–40）、+9增量。**14/1**：+5关系对象、+7增量，作用于符合原资格的我方成员；关系截到[-128,127]，原4219EC/462DD0。
- **15/0、3**为我方／敌方动作组头，+5容量；同旗标后续1/4为成员（+5角色、+7方向、+9动作组，执行动作×4），2/5为结束。
- **16/0、4**为我方／敌方移动组头，+5容量、+7镜头模式；1/5为成员（角色、x、y），3/7为结束；原422074也可在事件表尾终止。2/6角色相对操作数在当前解析器明确拒绝，需461808专项核对，不能按绝对坐标替代。

## 5. 对白行格式

每行23字节：+0 i16说话者，+2/+4 i16前／后音乐，+6起13字节姓名区（遇0结束），+19 u16文本偏移，+21 u16长度。文本位置相对该事件所有23字节行头之后；长度含末尾0，文本为原Big5字节。对白换行、框位置、头像与打字时间由引擎解释，不是把全部字节直接当UTF-8。

## 6. 物品、宝箱与存档边界

当前源码没有发现一个独立、通用的“宝箱记录表”或统一宝箱opcode，不能把地图上的物件号
直接解释为宝箱。已证实的物品相关路径有两类：

- 关卡角色记录的6个初始物品槽位位于角色表`+63`起，每槽2字节；加载时按ITEMSP中的物品
  类型重新分配到运行时装备槽，而不是保持源槽位顺序。
- 角色记录`+55`起的4个`initial_status` WORD在死亡/战役结算的物理掉落路径中被读取；
  `OriginalCampaignPersistence::try_collect_physical_loot()`将这些物品ID计入玩家库存，
  并按99件上限截断。该路径由角色状态/结算条件门控，不等同于地图上每个物件都能拾取。

事件本身的完成状态只保存每条事件的类型字节数组（`save_event_states()`），旗标、角色、
库存和关卡进度则由存档的其它字段保存。恢复时要求事件状态数组长度严格等于当前关卡事件数，
并只接受可表示为有符号8位的事件状态；因此扩展事件后，旧存档不能安全地直接沿用新事件表，
必须提供版本/迁移策略或隔离存档目录。

对新剧情的建议数据边界是：

1. 在BIN中新增或替换关卡表头、角色记录、文本区和20字节事件记录；
2. 在目标PRG域提供相同地图号及其地图格、特殊格、动作序列和属性/移动数据；
3. 在目标DAT域提供事件演出实际引用的背景、图标、部署或世界地图资源；
4. 为新增事件建立事件状态数量、旗标初值、路线/进度字段和存档迁移方案；
5. 对“宝箱”先从原汇编找到实际触发函数和资源字段，再决定它是事件奖励、角色掉落还是
   地图对象，禁止仅凭图片或物件编号命名。
