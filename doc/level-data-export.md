# 关卡数据导出方案

关卡数据不能按当前 PNG 目录导出。PNG 只表达显示结果，不能保留地形高程、地图索引、动态物件、事件指令、随机入口和敌我军表。

## 推荐格式

使用新的、只读的 `level-data/` 目录，每关一个二进制分片和一个校验清单：

```text
level-data/
  manifest.txt
  stage-001.prg.bin
  stage-001.dat.bin
  stage-001.events.bin
```

- `stage-XXX.prg.bin`：来自 `SUPERSP.PRG` 逻辑域的原始关卡条目，保留原始偏移表、长度和字节，不重新编码。
- `stage-XXX.dat.bin`：来自 `SUPERSP.DAT` 对应关卡条目，保留原始事件和战场背景引用。
- `stage-XXX.events.bin`：由反汇编确认的事件指令边界索引，保存 `offset,length,opcode`，操作数字节仍取自 `.dat.bin`，不复制或改写脚本。
- `manifest.txt`：版本、源文件 SHA-256、逻辑关卡号、原始条目号、长度、校验和；使用文本而非 JSON，避免把运行时格式误当成原版格式。

## 导出原则

1. 先按 `ResourceBundle` 的逻辑域恢复 PRG/DAT 条目，再按原 PAL 表和关卡索引建立映射；不能按物理合并文件偏移猜关卡。
2. 地图图形、地面动画和战场背景可继续导出到 `texture/`，但必须在清单中记录其原始条目号；它们不是关卡数据的替代品。
3. 事件指令只做边界索引，不把未知指令解释成自定义 JSON 字段。未知 opcode 保留原始字节并报告。
4. 导出必须写入新目录、检查源 SHA-256、拒绝覆盖已有目录；游戏运行时仍优先读取原始资源，直到逐关验证完成。
5. 首批应覆盖 1、71、已用于 smoke 的关卡和含传送／增援／胜败事件的代表关卡，再扩展到全量；每关以条目长度、事件边界和地图尺寸回归，而不是只检查文件存在。

该方案可同时支持逆向审计、外部工具查看和未来纹理化运行时，但不改变原存档或生产事件规则。
